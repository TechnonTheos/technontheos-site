Design complete

Two-site hospital network design

Problem: A network for a 200-employee hospital: a main campus with 140 staff and a remote campus with 60.

Built: A dual-stack IPv4/IPv6 design with four VLANs per site (Clinical, Admin, Support, Management), OSPF single area, HSRP at the core, DHCP, NAT, edge ACLs, SSH-only management, a /30 WAN link, and loopback addressing.

Two-zone enterprise lab on real hardware

Problem: Practice campus and branch networking on real Cisco gear, not just in a simulator.

Built: A Lab1 campus zone on OSPF and a Lab2 branch zone on eBGP. VRRP gateways across the 3750 and both 2811s. 3560 PoE access switches with BPDU Guard, DHCP snooping, and DAI. An optional L3 EtherChannel. I validated the design first in an FRRouting simulation, then wrote 14 setup and test documents (95 pages).

Complete

Firewall security review & hardening plan

Problem: Could any device on my network be pulled into a DDoS botnet?

Built: A read-only audit of the UDM Pro: port forwards, UPnP, IPS, and VLANs. I found the gaps (flat IoT network, unfiltered outbound traffic, no inter-VLAN segmentation, partial IPS coverage) and wrote a six-step hardening build sheet: an IoT VLAN, IPS on all networks, anti-spoofing, segmentation, outbound IoT filtering, and rollback steps.

Firewall policyIPS/IDSSegmentationIoT security

Building

Out-of-band console server

Problem: Reach every device's console without moving cables around.

Built: A Raspberry Pi with a 7-port USB hub and stable udev device names. It also runs ser2net for network console access, plus TFTP for config backups and rsyslog for central logging. I debugged silent consoles down to individual cables and USB-serial chipsets.

Linuxudevser2netSyslogTFTP

Building

Wireless: Cisco WLC and UniFi Wi-Fi 6/7

Problem: Full coverage across two floors, plus enterprise controller practice.

Built: A UniFi U6 Pro and U7 Pro deployment on each level. In the lab, a Cisco 5508 WLC runs lightweight 3502 APs, and one AP is converted to autonomous IOS.

Network automation with Ansible

Problem: Stop configuring every device by hand.

Built: A seven-phase plan based on Automate Your Network by John Capobianco, updated to current Ansible. The phases cover toolchain setup, reconnaissance, tactical changes, data models and Jinja2 templates, documentation generated from data, drift detection, and CI with GitHub Actions.
